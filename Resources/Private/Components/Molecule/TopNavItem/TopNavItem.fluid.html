TopNavItem — one destination in the top bar. An `a` when it has an href and a `button` when it has not, because that is the difference between going somewhere and doing something, and a screen reader announces the two differently. There is no `as` argument: which of the two you get is decided by whether the item navigates. The current page is said twice, on purpose. `data-selected` is what the tinted pill and the semibold weight hang off, and `aria-current="page"` is what a screen reader reads out — colour and weight say "you are here" only to someone who can see them. The stylesheet keys off either, so neither can be drawn without the other being announced. `layout="drawer"` is the same item inside the mobile drawer, where it stops being a pill in a row and becomes a full-width row in a list. That row shape lives on `.astryx-nav-item`, which a SideNav entry wears too, so the class is added alongside this component's own rather than copied into it — the same trick Card uses for its clickable affordance. The label keeps its own span in both layouts: it is the part that may be truncated, and the row rule that does the truncating needs an element to aim at. A selected item is the current page unless the caller says what kind of current it is. The empty string is ARIA's own "not current", so the ordinary item needs no branch of its own. {ariaCurrent}{f:if(condition: '{selected} == \'selected\'', then: 'page')} {f:if(condition: '{layout} == \'drawer\'', then: 'astryx-nav-item')}
