Dialog — the native `dialog`, opened with showModal(). The element does everything a React modal needs a library for: the top layer, the focus trap, the Escape key and a real ::backdrop are all the browser's. The only script left is the click that opens it, and that script finds the dialog by id — which is why `id` is required here rather than optional. Naming it is the part worth spelling out. A dialog with a visible title is named by that title, so passing `title` writes the header and points aria-labelledby at it; a dialog that is nothing but a video has no heading to point at, so it takes `ariaLabel` instead. Both attributes are always emitted and the unused one is empty, which assistive technology ignores — branching the element would have meant two copies of everything inside it. The header, the body and the close control are this component's, and `titleLevel` and `closeClass` are what let an element that used to write its own keep the heading level and the class it styled the control with. Overlay is a separate component and stays separate: a scrim over a picture is a decoration, a dialog is a mode. Sharing markup between the two would put a focus trap around a caption. `size` is the width: `sm` (the default, a confirmation), `md`, `lg` for a player or a gallery, and `full` for the whole viewport — what `variant="fullscreen"` has always meant, now a size so that it can be combined with a variant. `variant="media"` is the stage for a film: the dialog turns dark in either colour scheme, its title and close control with it, so a player's letterbox reads as the edge of the screen rather than as a white frame. A dialog closed with something still playing in it stops it: astryx.js pauses every video and audio element inside on close, and parks every iframe (its address restored on the next open), so a film does not go on talking behind the page. One aria-labelledby, not two. A caller pointing at a heading of its own wins; otherwise the title this component wrote names it.  The close button appears only once it has a name. An icon-only control with nothing to announce is read out as "button", which is no way out of a modal.
`astryx-dialog-body` is what makes a dialog's content scroll inside the frame instead of growing it, and a dialog holding one fixed-ratio frame wants the opposite. So it is a slot rather than a wrapper every caller writes: what goes in `body` scrolls, what goes in the default slot fills.
