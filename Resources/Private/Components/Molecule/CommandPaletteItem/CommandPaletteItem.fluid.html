CommandPaletteItem — one command in a palette: an optional glyph, what the command is called, and the shortcut that runs it without the palette. Like a typeahead suggestion, a palette row is an Astryx Item, so the label, the description and the two flanking regions are Item's parts rather than a third set of row rules. What this adds is the trailing keys. role="option" with a stable id, and aria-selected / data-state starting at "not this one" — the same division as everywhere else in this family: the server states what the row *is*, a script states which row is *current*. Without that script the row is inert, and deliberately so. An option is chosen through the combobox that owns it; giving it an href would either put a link inside a role="option" (invalid content, and the link disappears from the accessibility tree) or turn the listbox into a menu that the input no longer controls. `shortcut` is split on spaces and each piece becomes its own Kbd, so "Ctrl K" renders as two keys rather than one wide one. A single key with a space in its name is not a thing, so there is no escape hatch for it. The shortcut is not the row's accessible name and must not become it: it is read after the label, as the trailing region always is. A visitor who cannot see the keys still hears them, which is the only reason to print them at all.
  • The default slot is the leading glyph and nothing else. It is tested trimmed because an unfilled multi-line slot is whitespace, and a whitespace-filled region would still take its gap and leave every iconless row indented past the ones with icons. {label} {description} {key}
