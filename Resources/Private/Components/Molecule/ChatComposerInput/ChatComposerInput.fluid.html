ChatComposerInput — the field the visitor writes their message in. A `textarea` with a `label`, and not the contenteditable div every chat UI reaches for. A contenteditable is not a form control: it has no name, no value, it is not submitted with the form, it cannot be `required` or `readonly`, and a screen reader announces it as editable text with no idea what it is for. A textarea is all of those things for free, and the only thing it gives up is styled rich text, which a message box does not need. Growing with the text is CSS, not script: `field-sizing: content` on the field lets the browser resize it as the visitor types, and the stylesheet caps it so a pasted essay cannot push the composer off the screen. Where `field-sizing` is not supported `rows` is the floor and the field scrolls, which is the old behaviour and still a working one — that is why `rows` defaults to one line rather than being left to the browser's two. The label is real and visually hidden by default. A placeholder is not a label: it disappears the moment there is text in the field, it is not reliably announced, and several translation layers never see it. Pass `hideLabel="{false}"` where the composer is the page's main form and the name should be drawn. `id` has a fallback rather than being required, because a page has one composer and the label's `for` has to point somewhere; pass your own the moment there are two on a page.
