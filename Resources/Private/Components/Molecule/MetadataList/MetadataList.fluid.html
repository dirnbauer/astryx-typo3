MetadataList — label and value pairs: specifications, opening hours, the facts panel beside an event. A description list, and a grid rather than a stack of flex rows, so that every value starts on the same column however long the labels get. That alignment is the entire reason to reach for this instead of a list of sentences; a flex row would let each pair choose its own indent and the column would wander. `columns` is a number, not a token, and follows Grid's convention of a numeric data attribute. Above one column the grid stops aligning values across the whole list and packs the pairs instead, which is why each pair has to be a MetadataListItem to stay one unbreakable cell. The count is a ceiling, as Grid's is: two to four pairs a row where there is room, fewer where there is not, never more than asked for. `dividers="with-dividers"` draws a rule under each pair, the same word List uses for the same thing: a specification sheet, a credits list, opening hours. In one column the last pair has none, because a rule under the last row reads as the edge of something else; in several columns every pair has one, because no rule can know which pairs end the last row. A horizontal list draws the rule between the pairs instead. `size="sm"` sets both halves at the supporting size, for the lists that live in a footer and are read rather than scanned. Values are set in tabular figures, so prices, times and quantities in one column line up digit under digit.
