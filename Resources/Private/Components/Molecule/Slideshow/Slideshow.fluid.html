Slideshow — one view at a time, all of them stacked in the same place, the next one fading in over the last. Without script it is the PaginationDots pattern: every SlideshowSlide has an id, a dot links to it and `:target` shows it; with no fragment in the address the first slide shows. The runtime then takes the dots over, so a dot no longer scrolls the page to its slide, and keeps `aria-current` on the dot whose slide is showing. `interval` (seconds) makes the slides rotate. A view that changes by itself needs a way to stop it (WCAG 2.2.2), so the rotation exists only once `pauseLabel` and `playLabel` name the pause/play control this component then renders. It never runs for visitors who ask for reduced motion, waits while the slideshow is hovered, focused, off screen or in a background tab, and stops for good when a visitor picks a slide. The dots are the caller's: they belong wherever the design puts them, which on a hero is over the photo, outside this element. The runtime finds them by the slide ids they link to.
