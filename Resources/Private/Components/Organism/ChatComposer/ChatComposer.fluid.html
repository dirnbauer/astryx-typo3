ChatComposer — the form at the foot of a conversation: a field, a send button and, optionally, a microphone and a tray of options. Say what it is plainly, because the shape invites the wrong assumption. This is a form. It posts, the server appends the turn and the page comes back with the transcript one message longer. It does not stream, it does not append a bubble optimistically, and nothing on it updates while the visitor waits — there is no JavaScript in this extension. Everything the browser gives a form it has: Return submits, the field is restored on a back navigation, `required` blocks an empty send with the browser's own message, and it all still works with the stylesheet stripped. `method` is post, not get. A message can be long, a get would put it in the URL and into every log the request passes through, and the request is not idempotent — a reload should not silently say the same thing twice. The field is described by the hint rather than labelled by it, so a screen reader reads the label, then the field, then "press send" — as supporting detail rather than as the field's name. The hint id is derived from the field id so the two cannot come apart. The default slot is last and is meant for the hidden inputs a real posting form carries: a CSRF token, the conversation id, the model. It is separate from the `drawer` slot because those are visible controls and their order on the screen matters. Mind Fluid's rule when filling either: one `f:fragment` in a call and the loose children stop being the default slot, so use `` for the hidden fields as soon as you fill the drawer.
