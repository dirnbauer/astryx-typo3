PowerSearch — the search form a search *page* has: the query, the scope it runs in, and the queries this visitor ran before. It is not a second spelling of Organism/SearchForm, and the difference is worth stating because the two are one field apart on a screenshot. SearchForm is the header's: one field, one submit, and a loupe that the script collapses the pair into, built so that a visitor with no JavaScript still gets a working box instead of an icon that does nothing. It has no filters and no history, because there is no room for either beside a logo. PowerSearch never collapses and never sits in a header. It carries a scope the visitor can change, and it shows what they searched for last time — two things that need vertical room and a page to sit on. The scope is a real `select` inside a real GET form, not a row of links. A filter built out of links is a filter that throws away whatever is in the field the moment it is used: the browser follows the link and the query never gets submitted. A select submits alongside the query, which is the only arrangement that works with the script switched off — and the submit button is therefore not optional decoration, it is how the scope is applied. Recent queries are links and not listbox options, which is the opposite choice from Typeahead and for the opposite reason. These are known at render time and they are destinations, so an `a` gets them right: middle-click, keyboard, right-click-copy and a working page without script. The typeahead beneath the field is the live half and stays the script's — this form carries the same `data-suggest` attribute the header's does, so both fields get the same dropdown without either knowing the other exists. Nothing here writes a layout class. `astryx-power-search` has no rules anywhere in the stylesheet, so the arrangement is Layout/Stack and the parts are components that already own their appearance; the root class is a hook for a theme, not a promise that one exists.
An unclassed div, on purpose. astryx.js puts `astryx-typeahead-anchor` on whatever carries the anchor attribute, and that class is what makes the dropdown position itself — so the template marks the element and the stylesheet never has to know about a second one. It wraps the InputGroup rather than being it: an absolutely positioned menu inside the group would become a flex item of it and pick up the rules that weld the group's segments together.

A visible label rather than an aria-label on the list. The rows are old queries and read as plausible results on their own; sighted visitors need to be told what they are looking at just as much as anyone else does. {recentLabel} The explicit `li` is not redundant. An Item given an `href` renders as the `a` itself, and an `a` that is a direct child of a `ul` is invalid — the row needs a list item to be a row of.
