The browser's picker already speaks the visitor's locale and calendar, is reachable from the keyboard, and is the control their phone replaces with a native wheel. A calendar of our own would be a popover, a roving grid and a script — none of which exist here — and it would still show the date in the wrong order for half the people using it. Calendar, the component, is for showing a month, not for asking for a day. `min` and `max` are the real bounds and are emitted whether set or not: an empty one is not a valid date string, so the browser ignores it, which is exactly what an unset bound should mean. The value is always ISO — `2026-09-19` — whatever the field displays. That is the format the control takes and the format it posts, and passing a formatted date silently empties the field.
