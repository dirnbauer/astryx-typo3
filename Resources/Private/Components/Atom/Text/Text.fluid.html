Text — one run of body copy at a chosen role in the type scale. `type` is the role, not the size: `supporting` is smaller AND quieter in colour, `code` changes family as well as size, and the display steps borrow the heading family. Asking for a size directly would get one of the three and miss the other two. The display steps are fluid: a phone gets the step two below on the theme's scale, and the size grows to the step itself as the viewport widens, so a price or a hotline number set in display type is not set at a desktop's size on a 390px screen. `as` is separate from `type` for the same reason Heading keeps `level` and `type` apart. A definition term, a table caption and a figure caption all read as supporting text, but each has an element the browser and the screen reader already understand, and styling a `div` to look like them throws that away. The default is a paragraph because most text is one. `numeric="tabular"` sets every figure to the same advance width, so prices and quantities stacked in a list or a table line up digit under digit. Body type keeps proportional figures otherwise, which read better in running text. The display steps are tabular already. The attribute is written only when it is asked for.
