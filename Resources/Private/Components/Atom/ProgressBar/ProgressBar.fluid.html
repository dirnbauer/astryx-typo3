ProgressBar — how far along something is, as a figure and as a bar. The bar itself is decoration; the numbers are the content. `role`, `aria-valuenow`, `aria-valuemin` and `aria-valuemax` are what make the progress readable to anyone who cannot see the fill, and they are on the root rather than on the track because the whole component — label, figure and bar together — is the one thing being measured. An indeterminate bar deliberately renders no `aria-valuenow` at all. That is the ARIA convention for "progress is being made but the amount is not known", and it is not the same as zero: a bar that announces nought per cent while it slides back and forth is actively misleading. For the same reason the fill gets no inline width in that state, which would otherwise override the width the animation is built on. The fill's width is set inline because it is a continuous value and there is no other way to express it in CSS; `--value` is set beside it on the root so that an element's own stylesheet can read the same figure.
