ProgressBar — how far along something is, as a figure and as a bar. The bar itself is decoration; the numbers are the content. `role`, `aria-valuenow`, `aria-valuemin` and `aria-valuemax` are what make the progress readable to anyone who cannot see the fill, and they are on the root rather than on the track because the whole component — label, figure and bar together — is the one thing being measured. `decorative` is the other half of that sentence, and it is what three data elements need. They write the figure out in the row header as text and let the bar repeat it, so announcing the bar as well would read the same number twice; the widget semantics come off the root and the track is hidden from assistive technology instead. It is not a lesser mode — it is the honest one wherever the number is already in the page as words. An indeterminate bar deliberately renders no `aria-valuenow` at all. That is the ARIA convention for "progress is being made but the amount is not known", and it is not the same as zero: a bar that announces nought per cent while it slides back and forth is actively misleading. For the same reason the fill gets no inline width in that state, which would otherwise override the width the animation is built on. The fill's width is set inline because it is a continuous value and there is no other way to express it in CSS; `--value` is set beside it on the root so that an element's own stylesheet can read the same figure. A decorative bar sets neither: its value is a percentage an editor typed, `--value` comes from the element's own wrapper and the fill's width is a `calc()` in the element's stylesheet, which keeps the fraction an integer argument here would have rounded away. The label and the figure are slots rather than strings because both carry `f:render.text`, which is what makes them editable on the page itself; a string argument would be escaped and the editor markup would show as text. `labelAs` exists for the one element whose row label is a real heading: a roadmap stage is a section of the page, and a span would take it out of the document outline.
