DateRangeInput — from one day to another. Always the wrapper anatomy: there is no single input that means a range, so the border is drawn once around two `` fields and the stylesheet strips them back to plain text inside it. Two real date fields rather than a drawn range calendar, for the same reason DateInput is a native field — and because two fields are two tab stops, which is how somebody using only a keyboard sets the end of a range. Each field carries its own `aria-label`, and they default to nothing so a caller cannot forget to name them silently: the visible separator is a dash and `aria-hidden`, since "–" read out between two dates says nothing about which one is the start. The pair is not validated against each other here. A browser will not stop an end date before the start; pass the start as the end field's `min` from the template if the value is known, and check it again on the server, which is the only place it can be checked for certain.
