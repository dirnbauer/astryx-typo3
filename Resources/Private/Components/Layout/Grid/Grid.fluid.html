Grid — a set of equal children laid out in columns. `cols` and `fixed` are not two spellings of the same thing. `cols` is a hint: the CSS reflows on the space the grid actually has, and the number only tunes the minimum a column may shrink to, so a three-column grid in a narrow sidebar becomes one column on its own. `fixed` is a promise: the count is held whatever the width, which is what a numbered three-step process needs, because reflowing it into two columns would misrepresent the process. Pass one or the other, never both. The promise has two exceptions, both made in the stylesheet rather than by every element that used to make them itself. Four fixed columns are two on a tablet (641 to 1023px), where four would leave each one too narrow to read. And every fixed grid is one column on a phone — unless its items are small, see `items`. Neither count is a modifier token, so neither is emitted when it is zero: an absent column count is genuinely absent rather than a grid of no columns — and not an empty `data-cols=""` either, which a `[data-cols]` selector still matches. `gap` is a step of the spacing scale (1 to 12), the same values Stack takes; unset, the grid keeps its own 24px. `items="small"` is for grids of small things — logos, short figures, photo tiles, badges. On a phone a fixed grid of them keeps two columns rather than stacking into a column a thumb has to scroll past, and an auto-fitting one lets its columns narrow to 8rem before it gives one up. `as` exists because a grid of people or of steps is a list before it is a layout, and a list whose items are not in a `ul` or `ol` is announced to a screen reader as loose text with no count. `dl` is there for the same reason and was added later: seven metric bands laid their term-and-value pairs out on a grid, which made the `dl` disappear and every `dt` and `dd` in them an orphan — eighty-three of them, in one design review.
