ChatLayout — the frame a conversation sits in: the transcript, the composer below it, and the control that jumps back to the newest message. Only the transcript scrolls. The composer is a sibling of the scroller and not a sticky element inside it, because a sticky composer overlays the last message and the reader has to scroll past their own turn to read it. Two rows of a grid cost nothing and the transcript ends exactly where the composer begins. `endId` names the empty marker at the foot of the transcript, and it is there so ChatLayoutScrollButton has something to link to — an in-page anchor is the only scroll-to-bottom that works without script. The marker carries `tabindex="-1"` for the reason a skip link's target does: following the link should move the keyboard's focus starting point to the end of the transcript rather than leave it where the reader was. Layout composes nothing, so all three regions arrive as slots and this component never learns what a message or a composer is made of. Mind the Fluid trap when calling it: the moment you fill `composer` or `scrollButton` with an `f:fragment`, loose children stop being the default slot, so the transcript has to be wrapped in `` as well or it silently disappears.
An empty div and not an empty list item: the transcript slot holds the `ol`, and a marker inside it would have to be an `li` that a screen reader counts as a turn nobody wrote.
