Declared inside the section, not above it: a template or partial that is rendered through a layout or by section name never evaluates its root content, so a variable set out there is simply absent by the time the section runs — and every key built from it silently loses its path. One result is an Astryx Item, and it is the `li` of the results list rather than an `article` inside one: Item renders the row itself, which is what gives the list its dividers and the row its three regions. The title's link covers the whole row (see .g-search__result-title a::after), so the row is clickable without a second link competing for focus — exactly one tab stop per result. d:searchSnippet crops around the match and wraps the hit in , so the visitor can see *why* a result is in the list. Wrapped in a fragment of its own, and it has to be: the moment a component call contains one named fragment, Fluid stops collecting the loose children as the default slot and they render as nothing.
