The shell every single-control Powermail field shares: an Astryx Field holding a real label, the control, the help text and the message slot. Written once so the wiring cannot drift between twelve copies: - The label is a `label for`, never a title attribute; a field set to "nolabel" keeps a visually hidden one, because a control without a name is not a design choice. - "(required)" sits in the label as text, the way Astryx's Field writes its optionality, so it is not a colour or an asterisk only. - aria-describedby names the help text and, after a failed server check, the message — so both are read with the control. aria-invalid is set with the message, not instead of it. - The message slot (`…-messages`) is always rendered. Powermail's client validation writes its messages into it: every control points `data-powermail-errors-container` at it, overriding Powermail's default of appending a list wherever the control's parent happens to be. It is written on one line so it stays :empty, and hidden, until it has text.
